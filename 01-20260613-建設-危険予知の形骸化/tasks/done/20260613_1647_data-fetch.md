# データ取得（建設×危険予知 demoの土台）

## 目的・前提・方針案
- 目的: demoが読む「建設業の災害状況テキスト＋ラベル」を手元に用意する
- 前提: Sprintの割り切り＝一旦動けばいい。完全性・堅牢性より「問題文に使えるテキストが取れること」を最短検証
- 採用データ（notes.md §7-8）: JNIOSH公開 死傷災害DB CSV（`SHISYO_2006〜2017.csv`、12年分／UTF-8 BOM無し・カンマ・ヘッダ有・23列）。7列目=災害状況テキスト、8-13=業種、15-20=起因物、21-22=事故の型。`code.xlsx`でコード→名称
- 採用根拠: 一括DL可・約37.6万件・状況テキストに事故の型/起因物のラベルが既付＝クイズの問題文＝状況、正解＝事故の型、にそのまま使える。スクレイプ不要
- 割り切りの具体: まず直近1年（2017）×建設業フィルタのみ。全年・全件・差分更新はやらない。実装はPython

## 計画
### Phase 1: 取得可能性とデータ品質の確認（使い捨てスクリプト）
- [x] 利用規約 `/rule/rule.html` を一読 → 独自規約（複製・改変・転載は事前許可制、私的使用/引用は除外）。CC BYではない。要方針判断（ログ参照）
- [x] 実DL URL確定: `https://www.jniosh.johas.go.jp/publication/houkoku/ROUSAIDB/SHISYO_2017.csv`（200 OK・16.5MB・Content-Type text/csv）
- [x] DL→pandas読込: 31,496行×23列、ヘッダ日本語・UTF-8。災害状況=列[6]、業種大分類名=[8]、事故の型名=[21]、起因物大分類名=[15]、年齢=[22]
- [x] 建設業フィルタ→災害状況サンプル: 建設業3,900件。事故の型は墜落転落1332/はさまれ427/転倒400…。テキストは具体的で問題文に十分
- [x] 合否判定: 技術面PASS。本格利用はライセンス判断後（Phase 2着手のゲート）

### Phase 2: 本番フェッチモジュール（demoアプリが読むデータ層）
- ライセンス運用: データは実行時フェッチ＝コードのみ配布。CSV/スナップショットは.gitignore、実レコードは非commit
- [x] `.gitignore` に `**/demo/**/data/` を追加し、CSV/parquetがgit管理外であることを `git check-ignore` で確認
- [x] `demo/api/fetch_data.py` 実装: fetch（urllibで実行時DL）→filter（建設業）→normalize（7列抽出・rename）→save（parquet）。※名称列が元CSVに有り、code.xlsxは不要だったので依存削減
- [x] スナップショット形式: parquet採用（pyarrow 19あり）。load()がスナップショット優先で読み、無ければ生成＝オフライン動作
- [x] 年指定の単発取得に限定（引数 year、業種=建設固定）。再試行・全年・差分更新は未実装（割り切り）
